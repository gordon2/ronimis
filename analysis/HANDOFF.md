# Gym occupancy — анализ данных T1, август 2026

Хэндофф для новой сессии. Всё воспроизводимо: чистый Python 3, без зависимостей (numpy/scipy на этой машине нет).

## Исходный вопрос

Если идти в субботу в T1 на 3-часовую сессию — какое время самое тихое?

Осложняющий фактор: **залы не трекают выход**. Человек заходит, и включается таймер; после его истечения человек считается ушедшим. Поэтому число на дашборде — не текущая занятость, а скользящая сумма входов.

## Ответ

**08:00–11:00.** Реальная занятость в среднем 2.7 человека (пик 6.6 к концу окна). Худшее время — 13:00–16:00 (занятость 9.3, табло показывает 17.7).

Вечернее окно 20:30–23:30 по среднему близко (3.5), но хуже по двум причинам: пик приходится на начало сессии (8.3), и разброс между субботами огромный (5.4–19.6 против стабильных 2.3–4.4 утром).

## Ключевая находка: окно счётчика = ровно 180 минут

Измерено, не предположено. Метод: если `C(t) = Σ входов за последние N`, то `ΔC(t) = a(t) − a(t−N)`, откуда `cov(ΔC(t), ΔC(t+N)) = −var(a)` — у автокорреляции разностей должен быть резкий минимум ровно на лаге N.

| Зал | Минимум ACF | r |
|---|---|---|
| T1 | 180 мин | −0.300 |
| Mustika | 180 мин | −0.291 |
| Suur-Paala | 182 мин | −0.196 |
| Hipodroom | 180 мин | −0.302 |

Минимум острый и изолированный: на 2.5ч и 3.5ч корреляция ≈ 0. Независимая сходимость: медиана обнуления счётчика 02:24, последний вход ≈ 23:20 — разница ровно 3 часа.

**Следствие, важное для интерпретации дашборда:** табло систематически завышает при спадающем потоке. В 20:30–23:30 показывает 10.5 при реальных ~3.5 (втрое). На подъёме почти честное: 3.2 против 2.65. Правило: число растёт — верь; падает — реальность уже существенно ниже.

## Метод

1. Загрузка CSV, фильтр `status == success`, регуляризация на сетку 2 мин (шаг коллектора), линейная интерполяция пропусков.
2. Оценка окна счётчика по ACF разностей (см. выше). Наивная рекурсия `a(t) = C(t) − C(t−1) + a(t−N)` тоже даёт минимум на 3ч, но неустойчива — накапливает шум (см. `03b`, оставлен как отрицательный результат).
3. Профиль дня недели на сетке 10 мин, медиана по 5 субботам августа. Отсчёт суток начинается с **03:00** — там счётчик гарантированно 0, что даёт естественное граничное условие `a = 0` для деконволюции.
4. Деконволюция: NNLS `min ||A·a − C||² + λ||a''||²` при `a ≥ 0`, проекционный градиентный спуск. `A` — скользящая сумма окна 180 мин. rms реконструкции 0.68 при типичном C≈13 (~5%). Устойчиво по λ: 3 / 5 / 10 дают одинаковый вывод.
5. Реальная занятость `R_D(t)` = входы за последние D минут, для D = 60/90/120. Порядок окон не зависит от D.
6. Ранжирование 3-часовых окон по средней занятости, с ограничением на часы работы.

## Часы работы T1 (из данных)

Открытие ≈ **07:57** (медиана первого роста C), последний вход ≈ **23:20** (медиана обнуления 02:24 минус окно 3ч). Поэтому старт 3-часовой сессии позже 20:30 уже не укладывается.

## Открытые направления

- Деконволюция даёт локальный шум (например 16:30 → 0.4 входов/ч при соседних ~5) — плохая обусловленность задачи. Общая форма устойчива, но точечные значения на 10-минутной сетке доверия не заслуживают. Помогла бы более сильная регуляризация или сетка 20–30 мин.
- Длительность типичной тренировки D неизвестна принципиально: счётчик не видит выходы. Взяты сценарии 60/90/120 мин; выводы по выбору окна от D не зависят, но абсолютные числа занятости — зависят.
- Только 5 суббот. Расширение на июль + сентябрь дало бы 13–14 суббот и позволило бы отделить сезонность.
- Не проверялось, одинаково ли окно 180 мин во все дни и не менялось ли оно со временем.
- Остальные три зала посчитаны только по дням недели; полный анализ окон сделан лишь для T1.
